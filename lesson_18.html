1. Pydantic nima uchun kerak?

Oddiy dict ma’lumotni saqlaydi; masalan, {"age": "salom"} ham dict uchun to‘g‘ri. Pydantic esa kutilgan tuzilma va qoidalar asosida kiruvchi ma’lumotni tekshiradi, ayrim mos qiymatlarni kerakli turga aylantiradi va xatolarni tushunarli ko‘rsatadi.

Enum oldindan belgilangan variantlar to‘plamini nomlaydi: buyurtma holati, rol, to‘lov usuli. U Python standart kutubxonasida mavjud. Pydantic — alohida o‘rnatiladigan paket.

[email] qo‘shimchasi EmailStr uchun kerakli email-validator paketini ham o‘rnatadi. Buyruqlarni Windows PowerShell terminalida bajaring. Barcha keyingi misollarni loyiha interpreteri bilan ishga tushiring:

Pydantic ORM yoki database emas: ma’lumotni bazaga saqlamaydi, emailning haqiqiy egasini tekshirmaydi va foydalanuvchiga ruxsat bermaydi. Bular alohida biznes vazifalaridir.

2. Enum: nomlangan variantlar

Enum a’zosi name (nom) va value (qiymat)ga ega. Nom kodda, qiymat esa ko‘pincha tashqi API yoki saqlash formatida ishlatiladi.

from enum import Enum

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"
    CANCELLED = "cancelled"

status = OrderStatus.PAID
print(status.name)
print(status.value)
print(status == OrderStatus.PAID)
print(status == "paid")
print(OrderStatus("paid") is OrderStatus.PAID)
print(OrderStatus["PAID"].value)

3. StrEnum, IntEnum, auto va unique

StrEnum a’zolari string sifatida ham ishlaydi; Python 3.11 dan mavjud. IntEnum son qiymatlariga mos. Oddiy Enum bilan string/son Enumlarini aralashtirmang: tenglik xulqi farq qiladi.

from enum import StrEnum, IntEnum, auto, unique

@unique
class Role(StrEnum):
    USER = "user"
    ADMIN = "admin"

class Priority(IntEnum):
    LOW = 1
    HIGH = 2

class Mode(StrEnum):
    READ = auto()
    WRITE = auto()

print(Role.USER == "user")  # True
print(str(Role.ADMIN))     # admin
print(Priority.HIGH == 2)  # True
print(Mode.READ.value)     # read

@unique ikki nomga bir xil qiymat berilishini rad etadi. Usiz bir xil qiymatli a’zolar alias bo‘lishi mumkin. Oddiy Enumdagi auto() odatda o‘suvchi son, StrEnumda kichik harfli nom beradi. API uchun barqaror qiymatlarni aniq yozish qulay.

Python 3.10 uchun muqobil: class Role(str, Enum): .... Flag/IntFlag bitli kombinatsiyalar uchun ishlatiladi; oddiy bitta holat tanlash uchun Enum yetarli.

Shart va match bilan

# Yuqoridagi Role bilan davom eting.
role = Role("admin")
if role == Role.ADMIN:
    print("Admin roli tanlandi")

match role:
    case Role.ADMIN:
        print("Admin menyusi")
    case Role.USER:
        print("Foydalanuvchi menyusi")
Requestda "admin" to‘g‘ri Enum qiymati bo‘lishi uning egasiga admin huquqi berilganini anglatmaydi. Huquqlarni autentifikatsiya qilingan foydalanuvchi va server qoidalari belgilaydi.

default_factory har model uchun yangi qiymat yaratadi. Default qiymatlar odatda validatsiyadan o‘tmaydi; kerak bo‘lsa Field(default=..., validate_default=True) ishlating.

7. ValidationErrorni tushunish

errors() xatolar ro‘yxatini qaytaradi. loc — maydon yo‘li, type — xato kodi, msg — tushuntirish. Nested listda yo‘l masalan ("items", 0, "quantity") bo‘lishi mumkin.

from pydantic import BaseModel, ValidationError

class Quantity(BaseModel):
    value: int

try:
    Quantity.model_validate({"value": "abc"})
except ValidationError as exc:
    print(exc.error_count())  # 1
    err = exc.errors(include_input=False, include_url=False)[0]
    print(err["loc"])         # ('value',)
    print(err["type"])        # int_parsing
Xato ichidagi input foydalanuvchi yuborgan ma’lumotni saqlashi mumkin. Parol/token qatnashgan requestlarni to‘liq logga chiqarmang. Tashqi javobni loc, type va xavfsiz xabardan yig‘ing.

8. Strict mode va ConfigDict

from pydantic import BaseModel, ConfigDict, ValidationError

class Stock(BaseModel):
    model_config = ConfigDict(
        strict=True,
        extra="forbid",
        validate_assignment=True,
    )
    quantity: int

stock = Stock(quantity=3)
try:
    stock.quantity = "4"
except ValidationError:
    print("quantity int bo‘lishi kerak")

try:
    Stock(quantity=3, unknown=10)
except ValidationError:
    print("Ortiqcha maydon rad etildi")

strict=True tur aylantirishni cheklaydi. Model bo‘yicha, Field(strict=True) orqali bitta maydonda yoki model_validate(data, strict=True) chaqiruvida qo‘llanadi. JSONda mavjud bo‘lmagan turlar (masalan, sana) uchun ayrim qoidalar Python obyekt validatsiyasidan farqlanishi mumkin.

extra qiymatlari: "ignore" — standart, ortiqcha maydonni tashlaydi; "forbid" — xato; "allow" — saqlaydi. frozen=True attribute qayta berilishini to‘sadi, ammo nested listni chuqur muzlatmaydi. validate_assignment ham list.append()ni avtomatik tekshirmaydi.

9. field_validator: bitta maydon qoidasi

mode="before" xom qiymat bilan, mode="after" (standart) type validatsiyasidan keyin ishlaydi. Validator yakunda qiymatni return qilishi kerak.

from pydantic import BaseModel, field_validator, ValidationError

class Account(BaseModel):
    username: str

    @field_validator("username", mode="before")
    @classmethod
    def normalize(cls, value):
        if isinstance(value, str):
            return value.strip().lower()
        return value

    @field_validator("username")
    @classmethod
    def reject_reserved(cls, value: str) -> str:
        if value in {"admin", "root"}:
            raise ValueError("Bu username band")
        return value

print(Account(username="  ALI  ").username)  # ali
try:
    Account(username="ADMIN")
except ValidationError:
    print("Bu username ruxsat etilmagan")

ValueError validatsiya xatosiga o‘raladi. V2 da validator ichidagi TypeError avtomatik ValidationErrorga aylantirilmaydi; uni oddiy validatsiya xabari sifatida ishlatmang. Murakkab holatlar uchun wrap va plain validatorlari bor; plain standart type tekshiruvini chetlab o‘tishi mumkin.

Manba: Validatorlar qo‘llanmasi.

10. model_validator: maydonlararo qoida

from typing import Self
from pydantic import BaseModel, model_validator, ValidationError

class Period(BaseModel):
    start: int
    end: int

    @model_validator(mode="after")
    def check_order(self) -> Self:
        if self.end < self.start:
            raise ValueError("end startdan kichik bo‘lmasin")
        return self

print(Period(start=2, end=5).model_dump())
try:
    Period(start=5, end=2)
except ValidationError:
    print("Davr noto‘g‘ri")
{'start': 2, 'end': 5}
Davr noto‘g‘ri

Bu qoida sana oralig‘i, narx chegarasi yoki o‘zaro bog‘liq maydonlar uchun foydali. Modelning after validatori selfni qaytaradi.

11. Nested modellar va kolleksiyalar

from pydantic import BaseModel, Field

class Address(BaseModel):
    city: str
    postal_code: str

class Customer(BaseModel):
    name: str
    address: Address
    tags: list[str] = Field(default_factory=list)
    scores: dict[str, int] = Field(default_factory=dict)

customer = Customer.model_validate({
    "name": "Lola",
    "address": {"city": "Buxoro", "postal_code": "200100"},
    "tags": ["python"],
    "scores": {"math": "90"}
})
print(customer.address.city)  # Buxoro
print(customer.scores)        # {'math': 90}

list[Model] har elementni alohida tekshiradi. tuple[int, str] ikki pozitsiya turini, set[str] noyob matnlar to‘plamini ifodalaydi. JSONdagi set odatda arrayga aylanadi; tartibga tayanmang. Any turga oid tekshiruvni keng ochib yuboradi.

12. Enumni Pydantic bilan birlashtirish

from enum import StrEnum
from pydantic import BaseModel, ValidationError

class Status(StrEnum):
    PENDING = "pending"
    PAID = "paid"

class Order(BaseModel):
    id: int
    status: Status = Status.PENDING

order = Order(id=7, status="paid")
print(order.status is Status.PAID)       # True
print(order.model_dump(mode="json"))     # {'id': 7, 'status': 'paid'}

try:
    Order(id=8, status="unknown")
except ValidationError as exc:
    print(exc.errors()[0]["type"])       # enum

Standart rejimda qiymat Enum a’zosiga aylantiriladi. Strict Python kirishida Enum instance talab qilinishi mumkin. use_enum_values=True modelda a’zo o‘rniga uning qiymatini saqlashga olib keladi; default Enum uchun validate_default=True kerak bo‘lishi mumkin. Ko‘pincha modelda Enumni saqlab, JSON chiqarishda serializatsiya qilish yetarli.

Enum yoki Literal?

Literal["asc", "desc"] kichik, bir joyda ishlatiladigan variantlar uchun qulay. Enum ko‘p modelda qayta ishlatiladigan, nomlangan holatlar uchun qulay. Ikkalasi ham database qiymatlarini o‘z-o‘zidan yangilamaydi.

14. Alias, ORM obyektlari va TypeAdapter

from pydantic import BaseModel, Field, TypeAdapter

class PublicUser(BaseModel):
    user_id: int = Field(alias="userId")

user = PublicUser.model_validate({"userId": 12})
print(user.user_id)                          # 12
print(user.model_dump(by_alias=True))        # {'userId': 12}

adapter = TypeAdapter(list[int])
print(adapter.validate_python(["1", "2"]))   # [1, 2]

validation_alias kirish nomi, serialization_alias chiqish nomi uchun alohida ishlatiladi. Oddiy alias ikkala yo‘nalishga xizmat qiladi; alias bilan chiqarish uchun by_alias=Trueni aniq bering.

ConfigDict(from_attributes=True) dict o‘rniga obyekt attributelaridan model o‘qishga imkon beradi. ORM obyekt bilan ishlaganda kerakli attributelar oldindan yuklangan bo‘lsin. TypeAdapter class yozmasdan list[User] kabi turlarni tekshiradi; RootModel esa ildizi list yoki boshqa qiymat bo‘lgan model yaratadi.

16. To‘liq mini loyiha: buyurtma tekshirish

Quyidagi kod mustaqil ishlaydi. Xaridor emaili, mahsulot miqdori, narx, buyurtma holati, noyob SKU va umumiy narxni tekshiradi. Narx JSONga string bo‘lib chiqariladi — bu shartnoma frontend bilan kelishilgan bo‘lishi kerak.

from decimal import Decimal
from enum import StrEnum
from typing import Self
from pydantic import (
    BaseModel, ConfigDict, EmailStr, Field,
    ValidationError, model_validator,
)

class OrderStatus(StrEnum):
    PENDING = "pending"
    PAID = "paid"
    CANCELLED = "cancelled"

class Item(BaseModel):
    model_config = ConfigDict(extra="forbid")
    sku: str = Field(min_length=1)
    quantity: int = Field(gt=0, le=100)
    unit_price: Decimal = Field(
        gt=0, max_digits=10, decimal_places=2, allow_inf_nan=False
    )

class OrderCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")
    customer_email: EmailStr
    items: list[Item] = Field(min_length=1, max_length=50)
    note: str | None = Field(default=None, max_length=200)

    @model_validator(mode="after")
    def unique_skus(self) -> Self:
        skus = [item.sku for item in self.items]
        if len(skus) != len(set(skus)):
            raise ValueError("SKU takrorlanmasin")
        return self

class OrderResponse(BaseModel):
    id: int
    status: OrderStatus
    total: Decimal

def preview_order(payload: dict) -> dict:
    try:
        order = OrderCreate.model_validate(payload)
    except ValidationError as exc:
        return {
            "success": False,
            "errors": [
                {"field": ".".join(map(str, error["loc"])),
                 "code": error["type"]}
                for error in exc.errors(include_input=False)
            ],
        }

    total = sum(
        (item.unit_price * item.quantity for item in order.items),
        start=Decimal("0"),
    )
    response = OrderResponse(
        id=1, status=OrderStatus.PENDING, total=total
    )
    return {"success": True, "data": response.model_dump(mode="json")}

payload = {
    "customer_email": "ali@example.com",
    "items": [
        {"sku": "BOOK", "quantity": 2, "unit_price": "25.50"},
        {"sku": "PEN", "quantity": 1, "unit_price": "3.00"},
    ],
}
print(preview_order(payload))
print(preview_order({"customer_email": "bad", "items": []}))
{'success': True, 'data': {'id': 1, 'status': 'pending', 'total': '54.00'}}
{'success': False, 'errors': [
    {'field': 'customer_email', 'code': 'value_error'},
    {'field': 'items', 'code': 'too_short'}
]}

Ikkinchi natija o‘qish uchun bir nechta qatorga yoyilgan. Demo id=1 ishlatadi; real tizimda IDni database yaratadi. Productionda unit_priceni mijoz requestidan emas, server katalogidan oling; mijoz narxni o‘zgartira olmasligi kerak. PAID holatini ham server tasdiqlangan to‘lov asosida belgilaydi.

from fastapi import FastAPI

app = FastAPI()

@app.post("/orders/preview", response_model=OrderResponse)

18. Mashqlar, xatolar va bilimni tekshirish

  1. Priority Enum: low, normal, high. TaskCreate modeliga title (3–100 belgi), priority va optional deadline qo‘shing.
  2. Title bosh-oxiridagi bo‘sh joylarni olib tashlang; bo‘sh natijani rad eting.
  3. Buyurtma loyihasini quantity=0, manfiy narx, bir xil SKU va ortiqcha maydon bilan sinang. Xato joylarini yozib chiqing.
  4. Yaroqli modelni JSONga chiqaring va qayta o‘qing. Decimal hamda Enum turlarini tekshiring.
Enum validatsiyasi ruxsat nazoratini ham bajaradimi?

Yo‘q. U faqat ruxsat etilgan variantlardan biri kelganini tekshiradi. Foydalanuvchi aynan shu amalni bajarishga haqlimi — alohida tekshiruv.

str | None maydonini berish majburiy bo‘lishi mumkinmi?

Ha. Default bo‘lmasa, kalit majburiy, qiymati esa None bo‘lishi mumkin. = None qo‘shilsa kalitni tashlab ketish mumkin.

model_dump() va model_dump_json() farqi?

Birinchisi dict, ikkinchisi JSON string. JSONga mos dict uchun model_dump(mode="json") kerak.

Validator return qilmasa nima bo‘ladi?

Python None qaytaradi. Bu kutilmagan natija yoki keyingi xatoga sabab bo‘ladi. Valid qiymatni, model validatorida esa selfni qaytaring.

Amaliy yechim: TaskCreate
from datetime import datetime
from enum import StrEnum
from pydantic import BaseModel, Field, field_validator

class Priority(StrEnum):
    LOW = "low"
    NORMAL = "normal"
    HIGH = "high"

class TaskCreate(BaseModel):
    title: str = Field(min_length=3, max_length=100)
    priority: Priority = Priority.NORMAL
    deadline: datetime | None = None

    @field_validator("title", mode="before")
    @classmethod
    def trim_title(cls, value):
        return value.strip() if isinstance(value, str) else value

task = TaskCreate(title="  Python darsi  ", priority="high")
print(task.title)           # Python darsi
print(task.priority.value) # high
