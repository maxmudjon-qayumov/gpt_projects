Encapsulation — ma’lumotni himoyalash

Object ichki holatini nazorat qilish, noto‘g‘ri o‘zgarishlardan saqlash va property orqali xavfsiz API yaratishni o‘rganamiz.

Dars maqsadi

Encapsulation ma’nosi, public/protected/private kelishuvlari, name mangling, getter/setter, @property hamda backend validatsiyasini amalda o‘rganasiz.

1. Encapsulation nima?

Encapsulation — data va u bilan ishlaydigan methodlarni bitta class ichiga joylashtirish, object ichki holatiga to‘g‘ridan-to‘g‘ri noto‘g‘ri kirishni cheklash tamoyili.

Muammo

Har kim account.balance = -100000 deb noto‘g‘ri qiymat berishi mumkin.

Yechim

Balansni private saqlab, faqat deposit() va withdraw() orqali o‘zgartirish.

Asosiy maqsad: “Ma’lumotni yashirish” emas, balki data o‘zgarishini qoidalar orqali nazorat qilish.

2. Python’da access level kelishuvi

Python qat’iy private/public keywordlariga ega emas. Underscore’lar developerlar uchun kelishuv va ayrim texnik himoya beradi.

YozilishiNomiMa’nosi
namePublicIstalgan joydan foydalanish mumkin.
_nameProtected (kelishuv)“Ichki foydalanish uchun” degan signal; tashqaridan texnik jihatdan ochiq.
__namePrivate (name mangling)Python nomni _ClassName__name ko‘rinishiga o‘zgartiradi.
class User:
    def __init__(self):
        self.name = "Ali"         # public
        self._role = "admin"      # protected convention
        self.__password = "secret" # private

user = User()
print(user.name)   # Ali
print(user._role)  # ishlaydi, lekin tavsiya etilmaydi
# print(user.__password) → AttributeError
Muhim: __password haqiqiy security himoyasi emas. Uni user._User__password bilan olish mumkin. Bu faqat tasodifiy noto‘g‘ri foydalanishdan saqlaydi.

3. Nega method orqali o‘zgartiramiz?

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance

    def deposit(self, amount):
        if amount <= 0:
            return "Miqdor musbat bo‘lishi kerak"
        self.__balance += amount
        return self.__balance

    def withdraw(self, amount):
        if amount <= 0:
            return "Miqdor musbat bo‘lishi kerak"
        if amount > self.__balance:
            return "Balans yetarli emas"
        self.__balance -= amount
        return self.__balance
account = BankAccount("Ali", 100)
print(account.deposit(50))   # 150
print(account.withdraw(300)) # Balans yetarli emas
# account.__balance = -500 — haqiqiy private attribute’ni o‘zgartirmaydi

Class ichidagi qoidalar barcha o‘zgarishlarda ishlaydi.

4. Getter va setter usuli

Getter qiymatni qaytaradi, setter yangi qiymatni validatsiya qilib beradi.

class Product:
    def __init__(self, name, price):
        self.name = name
        self.__price = price

    def get_price(self):
        return self.__price

    def set_price(self, price):
        if price < 0:
            raise ValueError("Narx manfiy bo‘lishi mumkin emas")
        self.__price = price

product = Product("Telefon", 250)
product.set_price(300)
print(product.get_price())  # 300

Bu ishlaydi, ammo Python’da @property sintaksisi tabiiyroq ko‘rinadi.

5. @property — Pythonic usul

@property methodni oddiy attribute kabi o‘qish imkonini beradi. @x.setter esa atributga qiymat berilganda validatsiya qiladi.

class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price  # setter ishlaydi

    @property
    def price(self):
        return self.__price

    @price.setter
    def price(self, value):
        if not isinstance(value, (int, float)):
            raise TypeError("Narx son bo‘lishi kerak")
        if value < 0:
            raise ValueError("Narx manfiy bo‘lishi mumkin emas")
        self.__price = value
product = Product("Laptop", 800)
print(product.price)  # 800 — qavssiz getter
product.price = 900   # setter ishlaydi
# product.price = -10 → ValueError

6. Read-only property

Setter yozilmasa, property faqat o‘qiladi. Bu ID yoki yaratilgan sana kabi o‘zgarmas qiymatlar uchun foydali.

class User:
    def __init__(self, user_id, username):
        self.__user_id = user_id
        self.username = username

    @property
    def user_id(self):
        return self.__user_id

user = User(1, "ali")
print(user.user_id)  # 1
# user.user_id = 2 → AttributeError

7. Property deleter

class User:
    def __init__(self, email):
        self.__email = email

    @property
    def email(self):
        return self.__email

    @email.deleter
    def email(self):
        print("Email o‘chirildi")
        del self.__email

Deleter kam ishlatiladi; data o‘chirishni aniq nomli deactivate() yoki delete_email() methodida yozish ko‘pincha tushunarliroq.

8. Backend amaliy loyiha: parol va user

import hashlib

class User:
    def __init__(self, username, password):
        self.username = username
        self.__password_hash = self.__hash_password(password)

    def __hash_password(self, password):
        return hashlib.sha256(password.encode()).hexdigest()

    def check_password(self, password):
        return self.__password_hash == self.__hash_password(password)

    def change_password(self, old_password, new_password):
        if not self.check_password(old_password):
            return "Eski parol noto‘g‘ri"
        if len(new_password) < 8:
            return "Yangi parol kamida 8 belgi bo‘lsin"
        self.__password_hash = self.__hash_password(new_password)
        return "Parol yangilandi"
Production: parol uchun yalang‘och SHA-256 yetarli emas. Maxsus password hashing kutubxonasi (masalan Argon2/bcrypt asosidagi yechim) va salt ishlatish kerak. Bu misol faqat encapsulation logikasini ko‘rsatadi.
