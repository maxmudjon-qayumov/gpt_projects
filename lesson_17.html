1. Nega concurrency kerak?

Backend bir vaqtning o‘zida ko‘p foydalanuvchi so‘rovini qabul qiladi. Ba’zi vazifalar tarmoq/database javobini kutadi, boshqalari esa CPU’ni ko‘p ishlatadi. Concurrency vaqtni samarali ishlatadi.

Concurrency

Vazifalar bir vaqt oralig‘ida navbat bilan rivojlanadi. Kutayotgan task paytida boshqasi ishlaydi.

⚡

🌐

🧮

CPU-bound

Rasm/video qayta ishlash, katta hisob, ML inference kabi CPU ko‘p ishlatadigan ishlar.

2. Process nima?

Process — operatsion tizimda ishlayotgan mustaqil dastur nusxasi. Har process o‘z xotirasiga, Python interpreteri va resurslariga ega.

3. Thread nima?

Thread — bitta process ichidagi kichik bajarilish oqimi. Threadlar process xotirasini birgalikda ishlatadi.

import threading
import time

def download_file(name):
    print(f"{name} boshlandi")
    time.sleep(2)
    print(f"{name} tugadi")

t1 = threading.Thread(target=download_file, args=("file-1",))
t2 = threading.Thread(target=download_file, args=("file-2",))

t1.start()
t2.start()
t1.join()
t2.join()
print("Barcha download tugadi")

start() yangi threadda ishni boshlaydi. join() esa asosiy kodni o‘sha thread tugaguncha kutadi.

AfzallikKamchilik
Yengil; yaratish tez.Threadlar xotirani bo‘lishadi, race condition paydo bo‘lishi mumkin.
I/O-bound ishlar uchun yaxshi.CPython GIL sabab oddiy Python CPU-bound kodda ko‘p yadro parallelizmi cheklangan.
Data almashish osonroq.Debug va synchronization murakkab bo‘lishi mumkin.

5. GIL nima?

GIL — CPython interpreteridagi Global Interpreter Lock. Odatdagi CPython buildlarida bir vaqtning o‘zida faqat bitta thread Python bytecode bajaradi. Shu sabab CPU-bound Python kod threadlar bilan odatda tezlashmaydi.

Muhim noziklik: GIL I/O kutishda bo‘shaydi. Shuning uchun threads I/O-bound ishlar (HTTP, database, fayl) uchun baribir foydali. Ayrim native kutubxonalar ham GILni bo‘shatishi mumkin. Yangi free-threaded CPython buildlarida GIL o‘chirilishi mumkin, lekin keng tarqalgan muhitlarda GIL bor deb rejalash xavfsizroq.

Rasmiy glossary CPython GILni bitta threadda Python bytecode bajarilishini cheklovchi mexanizm sifatida ta’riflaydi. Python GIL hujjati.

7. threading: Lock va race condition

Race condition — bir nechta thread umumiy qiymatni bir vaqtda o‘zgartirib, kutilmagan natija berishi.

# Xavfli konseptual misol
balance = 100

def withdraw():
    global balance
    if balance >= 10:
        balance -= 10

Ikki thread bir vaqtning o‘zida balanceni o‘qishi va o‘zgartirishi mumkin. Buni lock bilan himoyalaymiz:

import threading

balance = 100
lock = threading.Lock()

def withdraw():
    global balance
    with lock:
        if balance >= 10:
            balance -= 10

threads = [threading.Thread(target=withdraw) for _ in range(5)]
for thread in threads: thread.start()
for thread in threads: thread.join()
print(balance)  # 50
VositaVazifasi
LockBir vaqtda faqat bitta thread critical sectionga kirsin.
RLockBitta thread lockni qayta ola oladi.
EventThreadlar o‘rtasida signal berish.
SemaphoreBir vaqtning o‘zida N ta kirishni cheklash.
QueueThread-safe task/data navbati.

8. Thread-safe queue.Queue

from queue import Queue
import threading

tasks = Queue()
for email in ["a@mail.com", "b@mail.com", "c@mail.com"]:
    tasks.put(email)

def worker():
    while not tasks.empty():
        email = tasks.get()
        print(f"Email yuborildi: {email}")
        tasks.task_done()

workers = [threading.Thread(target=worker) for _ in range(2)]
for w in workers: w.start()
tasks.join()
print("Barcha email yuborildi")

Productionda empty() tekshiruvi bilan qo‘lda worker yozishdan ko‘ra, yaxshi shutdown/signaling dizayni kerak bo‘ladi. Asosiy g‘oya: Queue threadlar orasida data uzatishni xavfsiz qiladi.

9. multiprocessing asoslari

from multiprocessing import Process
import os

def process_task(number):
    print(f"Process PID={os.getpid()}, son={number}, kvadrat={number ** 2}")

if __name__ == "__main__":
    processes = [Process(target=process_task, args=(n,)) for n in range(1, 4)]
    for process in processes: process.start()
    for process in processes: process.join()
    print("Barcha processlar tugadi")
Windows qoidasi: multiprocessing kodini if __name__ == "__main__": ichiga joylang. Aks holda child processlar modulni qayta import qilib, xato yoki cheksiz process yaratishi mumkin.

10. Processlar o‘rtasida data almashish

Processlar alohida xotirada ishlaydi. Oddiy global list child processda o‘zgarsa, parentda o‘zgarmaydi. Data uchun multiprocessing.Queue, Pipe, Manager yoki shared memory kerak.

from multiprocessing import Process, Queue

def calculate(number, result_queue):
    result_queue.put({"number": number, "square": number ** 2})

if __name__ == "__main__":
    queue = Queue()
    process = Process(target=calculate, args=(5, queue))
    process.start()
    result = queue.get()
    process.join()
    print(result)  # {'number': 5, 'square': 25}

Processga uzatiladigan funksiya va ma’lumot pickle qilinishi kerak. Lambda, ichma-ich funksiya yoki ayrim objectlar ishlamasligi mumkin.

11. concurrent.futures — tavsiya etilgan yuqori daraja API

ThreadPoolExecutor va ProcessPoolExecutor bir xil submit()/map() interface’ini beradi. Ko‘p holatda raw thread/process yozishdan sodda.

from concurrent.futures import ThreadPoolExecutor
import time

def fetch(url):
    time.sleep(1)  # API kutishini tasavvur qiling
    return f"{url} tayyor"

urls = ["/users", "/products", "/orders"]
with ThreadPoolExecutor(max_workers=3) as executor:
    results = executor.map(fetch, urls)
    print(list(results))
from concurrent.futures import ProcessPoolExecutor

def heavy_calculation(number):
    return sum(i * i for i in range(number))

if __name__ == "__main__":
    with ProcessPoolExecutor() as executor:
        results = list(executor.map(heavy_calculation, [100_000, 200_000, 300_000]))
    print(results)

Rasmiy dokumentatsiya ThreadPoolExecutor va ProcessPoolExecutor bir xil Executor interfeysini ishlatishini aytadi. concurrent.futures rasmiy hujjatlari.

12. Future va exceptionlarni olish

from concurrent.futures import ThreadPoolExecutor

def divide(a, b):
    return a / b

with ThreadPoolExecutor() as executor:
    future = executor.submit(divide, 10, 0)
    try:
        print(future.result())
    except ZeroDivisionError:
        print("0 ga bo‘lish mumkin emas")

submit() Future qaytaradi. future.result() natijani kutadi va worker ichidagi exceptionni shu joyda qayta chiqaradi.

16. Amaliy loyiha: parallel report hisoblash

from concurrent.futures import ProcessPoolExecutor
from collections import Counter

def analyze_chunk(statuses):
    return Counter(statuses)

if __name__ == "__main__":
    chunks = [
        [200, 200, 404, 500],
        [200, 201, 200, 404],
        [500, 500, 200, 200]
    ]

    with ProcessPoolExecutor() as executor:
        partial_counts = executor.map(analyze_chunk, chunks)

        total = Counter()
        for count in partial_counts:
            total.update(count)

    print(total)
    # Counter({200: 6, 500: 3, 404: 2, 201: 1})
Mustaqil mashq: 10 ta URL ro‘yxatini yarating. I/O vazifa sifatida time.sleep(1) ishlatadigan fetch() funksiyasini yozing. Avval oddiy for bilan, keyin ThreadPoolExecutor bilan ishga tushirib vaqt farqini perf_counter() bilan o‘lchang.
